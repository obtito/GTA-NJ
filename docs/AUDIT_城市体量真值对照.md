# 城市体量真值对照审计(2026-10-03)

**方法**:Overture Maps buildings(release 2026-09-23.1)bbox 下载南京核心区
(118.76–118.80°E, 32.02–32.06°N ≈ 4.2×4.4 km,16.8 km²,含玄武湖南岸/鼓楼/玄武区大部),
共 **13,975 栋**真实建筑轮廓(底面积>5m²),与本项目程序化城区在同 bbox 内逐实例对照。
取数管线:`overturemaps` CLI(bbox 过滤,10 秒/8.4MB);数据留存 `data/nanjing-buildings.json`。
OSM2World/Overpass 路线在本机网络均不可达(主 API/Geofabrik/镜像全被墙),Overture 是唯一可行真值源。

## 结果

| 指标 | 真值(Overture) | 程序化(GTA-NJ) | 偏差 |
|---|---|---|---|
| 楼栋数 | 13,975(**834 栋/km²**) | 主楼 149 + 裙房 73(4-9 块/km²) | 密度 0.01× |
| 底面积(中位) | **171 m²**(均 385 / p90 841 / p99 3,128) | **12,078 m²**(均 12,114) | **31×** |
| 占地率 | **32.1%** | 主楼 10.8% + 裙房 10.2% + 退台 1.3% ≈ **22%** | 0.69×(略稀) |
| 高度 | 有标签 435 株:均 70 / 中位 60 / p90 140 m | 该窗口:均 96 / 中位 108 / p90 158 m | 方向正确(样本偏塔楼) |

## 结论(三条)

1. **尺度范式差异,非错误**:本项目程序化城是「**街区体块**」风格——1 个实例 ≈ 1 个完整街区
   (格网 cell 1.2–1.7u = 120–170m),相当于把真值的 ~31 栋楼合并为一个体块。这是 GTA_SZ 一脉的
   风格化选择;底面积 31× 恰是「街区/单栋」的合并比。
2. **体量不胖,略保守**:总占地率 22% vs 真值 32.1%——程序化城比真实南京"稀"约三分之一
   (湖面/城墙/山体/道路/排除圆不吃楼也有贡献)。**不存在"楼盖得过大"的问题**。
3. **近景颗粒度是真实差距**:街区体块在航拍/中景成立,街景近看缺「栋」的分隔。
   若要补:把每街区拆为 5–15 栋真实尺寸楼(中位 171m²,可用本数据集的分布直接采样),
   即 BACKLOG 中「Overture/OSM 逐栋升级」路线,数据已就位。

## 复现

```bash
overturemaps download --bbox 118.76,32.02,118.80,32.06 -f geojson -t building -o data/nanjing-buildings.json
# 对照脚本见本文件方法节;程序化侧需 city.setGrowth(1) 后逐实例分解(buildCity 尾部自带 setGrowth(0),直读会量到种子态)
```
